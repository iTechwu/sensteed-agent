# Tools 分类展示与安装体验审查

## 问题与设计

用户截图中的 DoFe Tools 将多项业务能力压成一个入口，导致能力难以发现、连接详情混杂。本轮在插件侧栏与内置列表展开分类，点击每项定位自身详情。

| 分类 | 能力 |
| --- | --- |
| 检索与调研 | 行业与竞品调研、微信头条与西瓜公开资料、热点发现与事件跟踪、人才发现、客户线索发现与监测、汽车行业专项监测 |
| 内容分析 | 热门视频分析 |
| 运营与素材 | 小红书与抖音运营、文件上传与素材链接 |
| 供应链与企业 | 供应链数据检索 |

共十项能力，完整覆盖十二个 Tools 连接。它们共享 Tools 安装、启用和授权；不伪装成十个独立安装包，也不以启用状态表示连接健康。公开资料读取可能计费，写操作继续遵循原确认流程。

能力名称和说明源自 sibling 插件声明，连接归属记录于 `plugins/dsh-tools-mcp/capability-views.json`。桌面离线从已提交快照生成视图，门禁校验运行时声明、包元数据、视图和实际注册连接一致。布局和样式归产品仓拥有。

## 验证范围

每轮先通过相关检查，提交推送，按 main/tag 流程本地打包安装，再检查插件全部分类、十项详情、返回、滚动、键盘，以及主页、自动化、技能、知识九页、财务已授权页面、供应链六页和设置。

在真实账号中只读审查，不运行调研、采集、上传、财务写入或权限变更。不虚构参与者测试和 SUS 分数。外部连接故障单独记录，不作为视觉检查成功的证据。

## 轮次

第一轮：分类入口、分组概览、独立详情和来源一致性。
第二轮：依据安装版审查改进检索、列表定位和反馈，再打包安装复查。

Hub 正式发布须经过既有签名与证据门禁，源码同步和本地安装不等于 Hub 已发布。
