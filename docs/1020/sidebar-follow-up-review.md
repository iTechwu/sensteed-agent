# 侧栏与业务页面体验复查

## 本轮范围

依据 10 月 20 日的新截图继续修复，并在真实本地安装版进行两轮复查。以用户提供的 Codex 图作为视觉参考；采用专家体验审查，不冒充参与者可用性测试。

## 已确认原因与方案

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 收起态主页只有提示 | 原实现没有临时展开状态 | 复用已挂载会话树，悬浮或键盘聚焦展开，Escape 关闭，保留收起偏好 |
| 提示深浅不一致 | 内置入口与插件入口使用不同提示组件 | 统一窄栏入口提示；主页预览时省略重复提示 |
| 业务侧栏字体偏大 | 菜单继承外层字体 | 上下文栏固定 14px/20px、常规字重；分组 12px、行高一致 |
| 财务页面空白 | 访问检查未成功时 FinancePage 返回 null | 显式连接检查、失败说明与重新连接入口 |
| 供应链提示未连接、导航持续加载 | 宿主未发现供应链工具，菜单没有失败分支 | 保留真实失败原因，补齐导航不可用状态；不将连接故障当授权撤销 |

## 页面审查标准

主页检查项目与会话树、收起和临时展开、搜索保留、聊天三视图；自动化检查列表、搜索、创建入口与空态；插件与技能检查目录、已安装、详情返回与状态一致性；知识逐一检查九个子页；财务检查所有已授权子页；供应链检查六个子页及连接恢复；设置检查各分类、单一桌面入口和退出。

每页检查标题层级、字体密度、标签、滚动、键盘焦点、空态/加载/失败恢复；真实业务提交、审批和授权修改不用于只读体验验收。

## 源码与分发

插件唯一源为 sibling `docker-helm.dofe.ai/plugins`。共享导航桥先修改共享源，再由同步脚本分发至插件构建输入；插件检查后同步桌面 `.ci` 快照。源码和桌面快照均已推送 origin。

Hub 正式发布与源码同步是不同步骤。现有正式分发要求签名 release 和受审发布证据；本轮不得把源码提交或重新打包当作 Hub 发布成功的证据。

## 第二轮发现与第三轮修复

企业目录的技术回退包名难以识别，改为已知插件的业务名称；保留发布方自定义名称，并支持同时搜索业务名称与包 ID。知识治理页的读取动作置于结果前方，缩短未读取留白并限制表单宽度。供应链来源名称显示业务可读名称，保留原始来源数据。
