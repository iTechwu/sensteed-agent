# 逐页巡检与优化记录

## 结论与优先级

首轮发现三个基础问题：预载脚本在 DOM 根节点创建前挂载启动画面；财务数据中心把分页对象传给表格导致主面板白屏；本地 `file:` 插件的已安装副本滞后于 sibling 源码，造成新包仍运行旧布局。优先修复这些问题，再优化信息层级，避免仅用原型掩盖运行故障。

P0＝启动或主面板崩溃；P1＝主要任务受阻/状态误导；P2＝效率、阅读或可访问性问题。以下“已实现”指源码和回归已落地；最终包复验结果单列，不将源码通过等同于真实 App 已通过。

### 未被本轮 UI 修复消除的事项

1. **冷启动性能（P1）**：两次包内生命周期事件记录总耗时约 44.8 秒与 50.6 秒，Host boot 占约 42.0 秒与 47.6 秒，renderer startup 约 0.8 秒。已定位到阶段，尚未定位具体插件或 IO，不能宣称启动性能优化完成。下一步应对 Host 服务激活逐项计时，确认网络等待、MCP 初始化或插件依赖等原因后再改启动顺序，避免破坏当前依赖。
2. **预算版本差异接口（P1）**：0135 巡检中观察到后端返回 400，最终包没有重现该路径的全部业务参数组合；需要针对可比版本状态和接口错误契约继续复核，不能标为业务比较成功。
3. **外部服务与写入闭环**：供应商服务曾短暂失败、之后可读；真实财务提交/审核、知识写入、自动化执行、IM 发送和插件安装未在生产身份下执行。当前结论覆盖页面呈现、导航、授权读取与组件回归，不覆盖这些业务写入结果。
