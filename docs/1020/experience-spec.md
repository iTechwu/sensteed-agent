# 全页面布局与交互规范

## 信息架构

固定窄栏保持 52px，只承载跨模块切换：主页、知识与记忆、自动化任务、插件、技能，以及当前企业身份允许的业务插件。头像进入设置；不恢复独立设置按钮。项目与聊天、自动化列表、插件与技能目录、业务子导航分别归属第二层上下文栏，收起时完整移除上下文栏占位。

模块页保留自身上下文导航。聊天资源侧栏只在会话上下文显示，进入业务模块时释放占位，返回聊天后恢复原布局偏好。业务页面不得再渲染一套同级模块菜单。未知或尚在读取的授权状态不能被当作没有插件；确实无权限的入口不得出现。

## 阅读与视觉

沿用已确认的 Codex 灰阶方案和宿主浅深主题 token。标题表达业务目标，分组标题不冒充页面主标题。正文、表格和操作采用既有字体，避免装饰性渐变和新增图标体系。主内容适度限制宽度，数据密集页面可用完整工作区。选中项提供背景与语义状态，不能只依赖颜色。

原生桌面控件沿用 32–36px 紧凑高度；窄栏图标命中区域遵循已有设计，图形不随 hover 缩放。仅颜色、透明度等反馈过渡；侧栏列宽不做逐帧动画，以减少布局计算。尊重 reduced-motion。

## 状态与恢复

每个读取区域区分未读取、正在读取、成功无记录、读取失败、权限不足五种状态。未读取时给明确读取动作；请求失败提供重试，禁止伪造零值。异常列表对象不能让整个主面板崩溃，应限制在该表格内报告错误。切页后旧请求不能覆盖新页，提交中防重复触发。

内置能力状态和企业目录安装状态是两种事实：内置能力卡展示启用和授权；目录展示企业发布与安装。不将未发布伪装为已安装。技术连接名、JSON 响应保留在详情披露中，默认先读业务名称、状态和摘要。

## 表单与键盘

输入框必须有常驻可见标签，placeholder 只提供示例。管理控制台写入操作按任务折叠，展开后再显示参数，不改变既有权限与确认链路。提供可聚焦的工作区跳转入口，图标有名称与 hover 提示，模块栏/主内容/列表保留可访问性语义。

本轮只进行授权读取和导航；账户退出、授权调整、财务提交审核、插件安装、重建图谱等会产生业务变化的操作使用现有测试或组件验证，不在真实企业数据上执行。
