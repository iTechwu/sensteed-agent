# 2026-10-10 安装包体积审查

本轮原则：保留产品已有功能所需的 Codex、Claude、LibreOffice 等运行时，清理安装包中没有被使用的内容。没有将这些工具移出安装包，也没有改成首次使用时下载。

## 实测结果

测量对象为 `2.0.11-beta.21`、上游 `0.2.1-alpha.2`、Electron `44.0.0` 的本地 **arm64 未签名 DMG**。不是 universal 或正式签名版本的体积结论。原始字节数、安装包 SHA-256 和最大依赖清单见 [测量证据](2026-10-10-size-evidence.json)。MiB = 1,048,576 字节。

| 内容 | 优化前 MiB | 优化后 MiB |
| --- | ---: | ---: |
| DMG 下载文件 | 631.43 | 560.87 |
| app.asar | 690.15 | 428.76 |
| ASAR 外的运行文件 | 830.77 | 829.38 |
| ASAR 与外部运行文件之和 | 1520.93 | 1258.14 |
| 调试 source map 内容 | 208.80 | 0 |

下载体积减少 **11.17%**，应用运行内容减少 **17.28%**。运行内容统计不包含 Electron Framework、应用图标等 ASAR 外的应用资源；压缩安装包与展开后的应用不能混用同一个口径。ASAR 头部预留、文件过滤和压缩会影响物理尺寸，不能把所有源文件大小直接相加当成下载节省量。

## 已落实的清理

1. 在各平台的打包文件规则中排除 JS、TS、CSS 调试映射。afterPack 补入的原生依赖也清理映射，确保补入步骤不会绕过规则。构建目录仍生成调试文件，安装包不携带它们。
2. Electron 只携带产品支持的 `en-US` 和 `zh-CN` 语言资源。
3. 排除约 **81.9 MiB** 的未使用 `react-icons` 代码与声明。实际归档内的两处消费者均是 `dsh-better-sidebar/lib/client*.js`；所选图标已内嵌，其包名只出现在编译注释中。保留包元数据和许可证。检查实际归档的语法树，若将来出现 import、require、动态导入或其他字符串形式的真实引用，打包失败并要求恢复依赖。
4. 每次打包生成独立 `package-size-*.json`，统计 ASAR 物理尺寸、外部文件、调试文件、最大包和最大文件。原生文件只计一次，嵌套的不同依赖版本分别统计。CI 即使失败也上传这些报告。
5. 为应用运行内容设置预算：单架构 1.5 GiB，universal 2.5 GiB；超限保留报告后报错。TOS 发布另行拒绝超过 1 GiB 的安装文件，与现有自动更新器的下载上限一致。

## 打包体系的后续审查边界

- **先证明不可达，再删除。** 对大包检查生成后的客户端/服务端入口、动态加载、CSS/字体/worker 资源引用和插件配置，新增对应归档回归。检查源代码没有使用某个名称并不足以证明安装包里未使用它。
- **依赖声明与交付闭包保持一致。** 本轮补齐 worktree、translator 及 bundle 入口，并让生成器提前验证所有要求的一方包均直接声明；保留 Loader 和真实归档检查。不要通过削弱闭包验证来缩小体积。
- **按平台清理原生预构建。** 既有规则已排除大量其他操作系统的运行时。基线残留的其他架构/平台文件约 2.5 MiB，不是主要占用；进一步清理需逐一确认加载路径。Mac universal 必须保留两种 CPU 的必需内容。
- **不要直接切换 Mac 发布架构。** 当前 Mac 默认和正式发布使用 universal；TOS 发布器及更新清单也按 universal 识别。拆成两个架构属于交付协议变更，需要同时调整发布器、服务端更新响应和客户端选择逻辑，不属于本轮“未使用内容清理”。
- **持续按实际平台产物校准预算。** 此处实测只覆盖 arm64；Windows、Linux、Mac universal 以其 CI 报告和安装包验证为准。应用预算与下载文件限制分开检查。

## 相关失败修复与验证

上游升级后缺少的 worktree、translator 和间接 bundle 已补充到桌面依赖。删除 Windows 中指向旧 pnpm 路径的 fs-ext 重建命令；Windows 使用另一套文件锁实现。Loader 验证改为当前的 webStartup 注入。

完整检查还修复了两类已有测试问题：AA 2.0.2 已可启动，旧冒烟却要求它等待或导入失败；ASAR 3 返回尚在写入的流，测试需等待 finish 后再修改/读取归档。双架构原生编译的独立测试时限也与其真实工作量对齐。

Knowledge 的前端测试失败是国际化与导航 mock 边界过时，已修正。其前端 50 个文件、227 个测试和完整 quality:gate 通过，API 155 个套件、1458 个测试通过。集成测试阶段没有发现测试，不能将其描述成实际集成场景全部通过。
