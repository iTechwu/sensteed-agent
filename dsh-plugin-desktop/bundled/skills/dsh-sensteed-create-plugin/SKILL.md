# 创建 Sensteed 插件

把用户的需求推进为当前 Sensteed Agent 中可用的 DSH 插件。沿用 Harness 的插件开发协议和安装工具，不另造插件格式。

## 开始会话

- 点击菜单只代表开始创建流程，不包含具体插件需求。若启动消息没有说明用途，立即用用户的语言问：“你想让插件帮你完成什么任务？可以描述使用场景、输入和期望结果。”可给出两个简短例子，等待回答；不要自行选题或生成空壳插件。
- 已有明确需求时复用会话信息，只补问阻塞实现的细节。用一句话确认要交付的行为，再开始实现。

## 实现与安装

1. 使用 `skill` 工具加载 `cordis-plugin-development`（参数 `{"name":"cordis-plugin-development"}`），并遵循其中的工作流及按需引用的文档。它是插件结构、Host/Client 边界、Slots 和安装方式的依据。
2. 使用可用的 `cordis_inspect_list`、`cordis_inspect_query` 等检查工具核实当前运行时的服务、工具和扩展点。按需查询，勿凭记忆编造 API；不存在通用的 `create_plugins` 方法。
3. 在当前工作区的独立目录创建真实插件包，补齐包元数据、入口与所需的界面信息。不要在 `$DSH_HOME`、运行中的 profile 或应用安装目录直接写插件源码，也不要直接编辑 profile 的 `package.json` 或 `cordis.patch.yml`。
4. 按插件实际行为完成构建、类型检查和适当测试。含界面的插件检查入口、加载、空态与失败反馈；含外部连接的插件遵守当前工作区的连接与权限规则。不要把未执行的检查写成通过。
5. 使用 `plugin_manager` 的 `install_bundle` 动作安装已验证的插件，`target` 为插件包的绝对目录；遵守工具实际的参数定义、审批和返回值。安装到当前 profile 后确认可发现、可加载；未安装或加载失败时清楚说明并修复。

## 交付

说明插件解决什么问题、从哪里使用、源码目录、已完成的验证和安装状态。若缺少开发技能、必要工具或权限，明确指出阻塞项和可继续的步骤，不以“已创建会话”或“已生成文件”冒充插件可用。发布到公共仓库或市场、远程部署应以用户的明确请求为依据。

加载此技能的路径可能位于打包应用的 `app.asar` 内。使用 Host 提供的读取工具访问技能及其引用文档，不用 shell 的 `ls`、`cp` 等操作假设它是普通目录。
