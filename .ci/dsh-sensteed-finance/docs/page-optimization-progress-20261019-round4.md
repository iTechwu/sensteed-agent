# 财务页面剩余优化：2026-10-19 第四轮

承接[第三轮剩余清单](page-optimization-progress-20261019-round3.md)，本轮完成部门归属的登记与日期解析交互。Datasource 源码提交 `71cba03`（main）；插件源码、构建产物与本记录一并提交。未执行 Jenkins、生产部署或桌面发布。

## 本轮逐项对照

| 页面 / 操作 | 原有差异或缺陷 | 本轮结果 |
| --- | --- | --- |
| 人工补录归属 | 网页缺常驻日期标签；两端字段缺失时按钮静默禁用 | 统一必填标签、可用人员/部门与日历日期校验。提交空表单会显示字段错误、关联说明并聚焦首错；目录加载失败或无可用选项仍阻止登记。 |
| 生效时间与确认 | 缺少保存前人员/部门/生效时点摘要 | 两端展示人员→归属部门、日期、当地时间 00:00 生效及旧记录自动闭合说明；动作统一为“登记 / 登记中…”。历史归属的最终切分仍由服务端裁定。 |
| 无效日期 | 日期直接调用 toISOString，可能异常或将 2 月 30 日进位 | 两端登记和预览统一严格日历规则；保留既有当地零点语义，无效日期不请求服务端。 |
| 切换人员 | 未保存部门和日期被直接清空 | 网页先确认，可继续填写保留原人员与内容，放弃后才切换并清空部门、日期和解析日期。插件独立归属页弹窗固定所选人员；兼容代录入口允许切人，但同样先确认未保存输入。 |
| 失败与重复提交 | 网页只有泛化 toast；插件取消按钮绕过脏退出 | 两端就地提示失败并保留输入，提交锁防止重绘前连点。插件提交期间禁止关闭，取消/关闭/Escape/遮罩走相同未保存确认；两端脏表单保留刷新关闭保护。 |
| 按日期解析归属 | 网页有入口，插件独立归属页缺入口 | 插件补齐只读解析预览，使用既有 `/finance/employment/resolve` 公开 REST 契约。选择日期后查询当前人员，加载、错误重试、未匹配分别显示；切人重建预览，登记成功触发刷新。 |
| 共享交互 | 网页复用未保存保护会依赖整个财务代录弹窗 | 将原有 guard 原样抽为轻量 hook，旧导出保持兼容，避免部门归属拉入全部代录表单。插件复用通用字段和离开保护，增加切人确认动作与固定字段支持。 |

网页继续使用页内补录，插件继续使用桌面弹窗；本轮统一业务步骤与输入规则，未将全部页面容器改为完全一致。

- 插件 `npm run check`：构建、语法与 **217 项测试通过**。覆盖空表单、首错定位、切人确认/保留/放弃、失败保留、重复请求、提交锁、预览有效/无效日期与错误态。

- 跨端检查通过既有 25 个业务目的地、权限/契约/报价/问答对照，新增 12 个归属日期用例，并分别在默认时区与 `America/New_York` 执行，含闰日、无效月日及夏令时切换日。
