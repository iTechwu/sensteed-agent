# Datasource 与 Sensteed 财务插件产品体验审查

审查日期：2026-10-16。生产目标为 `https://ds.hozonauto.com`；浏览器访问跳转统一登录，未执行真实财务写入。网页源码检查以 Datasource `d3487e0`（任务导航）、`bc0f3d6`（2027 配置）及本次 `1243877`（回填识别）为依据。检查期间两个工作区持续有并行修改，本次仅提交本任务所属差异。

## 结论与处理

共同业务 API 不能自动保证共同产品体验。原来网页按工作域组织，插件将业务模块平铺，并把财务代录、填报活动、个人任务及身份维护混在同一个入口。用户需要重新学习入口、保存语义和上下文。本次以业务任务作为对应关系，保持服务端鉴权、财务口径与部署边界。

| 严重度 | 具体问题 | 本次处理 |
| --- | --- | --- |
| 高 | “录入”同时包含财务直录、部门任务和人员维护 | 代录、四类填报入口、三类身份维护分别进入；普通部门角色不看到直录 |
| 高 | 通知只根据路径前缀跳模块，预算比较落入预算执行，任务与年度丢失 | 精确解析本站业务路径；保留任务、年度、主体；兼容旧填报链接；未知路径说明不可用 |
| 高 | 网页新增 2027 部门/费用映射，插件仍为独立平铺字段 | 同用年度配置快照，依次选择部门和费用层级；自动派生分类；上级变化清空下级；缺配置禁止保存 |
| 高 | 回填切换付款/收入后保留另一类记录的金额和日期 | 类型切换同步重置计划、金额和日期，年度保留 |
| 中 | 回填记录同名，主体、月份和金额不可同时核对 | 两端统一显示标题、主体、期间、金额、编号，零金额与缺失明确区分 |
| 中 | 网页可就地新增科目，插件无入口 | 其他年度的财务负责人可调用维护接口新增并选用；失败保留；同步锁防重复；Enter 不提交外层预算 |
| 中 | 年度在插件头部和表单内重复，用户难以判断写入年度 | 代录只在表单显示年度，更新工作台年度；变更后清空旧输入，保持录入类型 |
| 中 | 付款/收入字段顺序不同，金额在业务明细之后 | 主体与年度 → 期间与金额 → 业务明细；必填提示与单位显式展示 |
| 中 | 窄窗口出现多组横向导航，难以寻找任务 | 900px 以下使用同一分组的页面选择器，表单单列；390px 验证无横向溢出 |

## 表单交互约定

1. 先明确主体、年度和期间，再确认金额与业务明细。金额以元录入；年度不分月必须明确可见。
2. 目录字段提交 ID；历史文本允许明确确认自定义值。输入搜索词不等于完成选择。
3. 2027 年预算必须使用有效配置组合，不能手写映射、自动建版本或回退普通科目录入。其他年度可选科目留空遵循原契约。
4. 财务代录保存即生效；部门填报先暂存/提交，财务再确认。两种语义不得用一个“录入”入口掩盖。
5. 在途请求锁定相关编辑和重复提交；失败保留输入并展示业务错误；成功重置本次输入、保留年度并刷新数据。
6. 回填识别信息由独立格式函数产生，两端输出相同。切换计划类型必须清掉另一类型的实际金额和日期。
7. 财务角色、写入能力、活动管理能力及身份维护角色分别检查。界面入口控制不能替代服务端鉴权。

## 第二轮核查：预算逐条审核与业务链接（2026-10-16）

实际浏览器只读核对 `https://ds.hozonauto.com/filing/budget`：网页已经展示“本人填报 → 对接人初审 → 负责人终审 → 部门整体提交 → 财务确认”，并在“我的工作”下拥有独立菜单。此前插件没有这个目的地，预算活动仍打开普通多行填报弹窗，因此仅有菜单同名不足以实现业务一致。

| 发现 | 用户影响 | 本轮处理 |
| --- | --- | --- |
| 缺少 `/filing/budget` 及四个逐条预算接口 | 两端预算审批链不同，通知无法定位 | 插件新增“预算填报与审核”，采用同一公开 REST 契约；普通填报中的预算记录引导到此入口 |
| 插件自行按角色判断写操作 | 自定义岗位与数据范围可能和按钮不一致 | 新工作台仅展示服务器返回的 `rows[].actions`、`departmentActions`、`canCreate`、`canCopy`；提交携带 revision，由服务端继续校验 |
| 网页费用类别是不可搜索原生列表，月份自由输入 | 与插件和代录页交互不同，长字典查找困难 | 两端均先选费用类别，再选月份、输入元金额和编制说明；网页使用已有 FinanceOptionPicker，月份采用固定选择 |
| 网页切年不更新 URL、不清除 task | 新年度仍带旧活动 ID，刷新后回到旧范围 | URL 作为年度来源；切年清除活动、分页；历史活动链接先定位实际年度；非法链接明确报错 |
| 网页退回操作在请求前关闭弹窗 | 请求失败后原因丢失 | 成功后才关闭；失败保留原因和可重试提示；新插件同样处理 |
| 仅靠 busy 状态防重复 | 快速双击可在重渲染前触发重复写入 | 表单和审核动作采用同步锁；插件保存期间阻止遮罩、Escape 和关闭按钮中断 |
| 复制下一轮和历史归属缺少对应界面 | 用户必须换端完成预算调整 | 插件增加下一轮草稿、调整原因、截止时间和组织人员选择；禁止自由填写人员 ID |
| `/cash?tab=revenue`、`recordType=ESTIMATED` 等参数被丢弃 | 同一链接在插件落到另一张表 | 白名单映射保留资金子页面、PR 类型、月份、部门、版本和预警条件，并在相应视图消费 |
| 执行率旧公式包含预计 PR，金额说明固定写万元 | 与网页的口径认知不一致 | 执行率按已打 PR / 年度预算；预计 PR 独立展示；未知金额不补零；明确元及万/亿缩略单位；已打/预计 PR 分别下钻 |

## 第三轮核查与实施（2026-10-17）

本节更新前两轮的预算直录和权限说明；早期记录描述的是当时行为，不能继续作为当前产品规则。源码依据为 Datasource `626a7ac` 及其之前的正式预算禁直录、年度费用映射、Excel 与审计提交。生产网站本轮访问进入 SSO 登录，没有执行真实财务写入或权限变更。

### 发现与修正

| 问题 | 统一后的行为 |
| --- | --- |
| 网页已关闭正式预算直录，插件仍找已发布主版本并直接保存 | 所有年度的“预算行”入口均引导到预算填报；保留年度。保存为本人草稿，经初审、终审、部门提交与财务确认后进入预算版本；已发布预算走预算调整 |
| 年度配置只在旧代录页使用，逐条预算仍使用全局科目 | 两端使用服务端返回的部门年度映射，一级费用 → 费用科目与分类 → 月份 → 元金额 → 编制说明；切一级清空下级；缺配置禁止保存，不回退全局字典 |
| 插件丢失版本筛选，历史版本链接默认附加当前年度 | 两端版本可搜索并展示状态、短编号；历史活动/版本未带年度时先定位服务端真实年度；切换年度清掉旧活动、版本、记录定位 |
| 插件缺 Excel 追加预算，且 Host 的 256 KB 限制容不下网页允许的文件 | 增加模板、整份预览、逐行错误及显式确认追加；预览指纹传回服务端，重复导入不重复新增。仅两个精确 Excel 上传接口允许 768 KB JSON，普通写入仍为 256 KB；原文件上限 512 KB |
| 插件不能查询操作时快照 | 同一授权历史接口分页展示操作人、原因、状态和变更前后条目，以及上一轮对比；无旧快照明确告知，不能用当前条目冒充历史 |
| 网页发生业务冲突时丢弃服务器原因 | 网页预算保存、审核、复制和归属调整保留服务器业务原因与输入，便于核对再试 |
| 插件权限页仍为旧叠加授权，缺逐条审核能力码及自定义岗位 | 使用完整成员/岗位策略；成员独立策略覆盖角色，移除后恢复继承。按有效管理权限开放管理；组织目录选人含下级、排除不可用身份，批量成员是当时快照。支持岗位维护及批量分配，分配角色保留成员独立策略 |
| 权限变更只确认一次，修改范围后仍可沿用旧确认 | 确认绑定对象、成员、全部功能与数据范围；任一变化须重新确认。零功能明确为全部关闭；服务器继续鉴权和原子校验；失败保留，快速双击只发一次 |
| Agent 指引仍含预计 PR 的旧执行率和正式预算直写工具 | 指引同步使用已打 PR / 年度预算；预计 PR 独立展示；预算新增转到草稿审核链 |
